# DLNA Video Server Public v0.4.3

v0.4.2からの更新です。Private/Publicの製品バージョンは共通0.4.3です。既知の制限を開示した正式リリースであり、全互換性問題の解決を意味しません。

Node.js24.22.0同梱、FFmpeg/ffprobe非同梱の標準Windows x64 ZIPです。従来どおり外部FFmpegを使用します（PC検証基準8.1.2）。

## 主な変更

- 観測された受信機実装と入力の技術条件を分けて判定し、適格なAVI/WMV入力とMPEG-2/AAC二音声の互換性を改善しました。DMS広告を再生クライアント能力と混同しません。
- 対象のMPEG-2出力経路で、適格な特殊色情報のMP4をBT.709/limitedへ実画素変換し、元の通常一覧から再生できるようにしました。色変換はfilter_threads=1です。
- カタログの色情報補完、入力適格性、復号中の色・時刻変化、JIT監査・異常終了時の後処理を強化しました。64ms監査は維持しています。
- 役割を終えた隔離DBR互換性試験タブ、30秒固定資産の準備/一時公開、専用API/URLを撤去しました。旧ファイルが上書き先に残っていても再有効化しません。
- v0.4.2の仮想フォルダー、ObjectID、通常TS/Direct Play、既存AVC CFR/VFR・Seek経路を維持します。放送日時・チャンネル表示機能は追加していません。

## 確認済みの範囲

- **実機確認**：DBR-T1010で代表的な特殊色MP4の通常一覧からの再生、二音声切替、約120秒Seek、Seek後の再切替をユーザーが確認済みです。先行版のAVI/WMA Pro再生・音声切替成功も確認されています。全受信機・全素材の保証ではありません。
- **PC確認**：公開コードと再生実装が同じ候補で、代表MP4の約25分12秒の全編HTTP配信、独立PCM照合、AAC PID321/322、64ms終端・TS/PCR/PTS監査、正常終了/解放を確認しました。配布物の起動/停止・更新/復旧、Private/Publicの自動回帰も検証しています。
- **未確認**：上記MP4のテレビでの全編自然終了、同系統全素材や別受信機での成功、あらゆる高負荷条件を保証していません。

## 色正規化の対象と更新時の注意

対象は現在の受信機/endpointと照合したMPEG-2経路、MP4のH.264 Main/High（level4.1以下）、8bit4:2:0 progressive、1920×1080以下、約23.976fps、明示full-range/SMPTE240M、時刻が整合したAAC LC48kHz stereo二音声です。作品名・個体UDN・素材fingerprintの登録を通常動作の前提にしませんが、既存の明示拒否・例外と入力適格性を維持します。

full-range全般、HDR/10bit、特殊色の一音声入力への一般対応ではありません。未対応の入力や途中異常は拒否/停止し、危険な元入力へfallbackしません。旧H.264 MP4/HEVC MKVの不足情報は既存の直列ヘッダー解析で補完し、完了まで該当MPEG-2リソースを非公開にします。解析無効/失敗時は補完待ちになります。項目/ObjectID/運用データは保持します。

## 既知の制限・未解決事項

- **DBR-T1010のWMV Seek復帰が不安定**：冒頭付近・途中の双方で、Seek後に再生が戻らず停止ボタンで終了する事象があります。直接原因は未特定で、v0.4.3で発生した回帰とも確認できていません。PCの復号成功や受信機切断を、実機復帰成功としていません。
- **AVIの開始直後Seek**：代表H.264/MP3二音声AVIの約0.1秒へのSeekで音声開始が遅れ、監査失敗で配信が終了するPC再現があります。通常の12秒等の成功から全Seek位置の正常性を保証しません。
- **WMA Pro自然EOF**：一部素材は音声終端差が64msを超え、全編終端でHTTP異常終了します。研究用PCM索引時計は通常経路へ組み込んでいません。
- **WMA v2**：末尾の無音約64msと再生終端契約、および特定区間の副音声PCM相関未達が未解決です。閾値を緩和して合格扱いにはしていません。
- **MKV**：元映像の約417ms間隔や復号警告が残る素材があります。Vorbis副音声は未対応です。
- 一部受信機のCFR必要性は互換性情報からの推定で、全型番の実機検証済みという意味ではありません。
- 位置指定のない再GETでは再生位置の維持を保証しません。送信量や経過時間で要求位置を推測補正しません。

## 更新・復旧

旧版を正常停止し、既存のバックアップ手段で設定・許可・整合DBを保全してからアプリを上書きします。同じlauncher/データ領域を継続使用し、Setupの再実行は不要です。設定・UDN・catalog・ObjectID・PCR/Seek索引等の運用データを配布物で上書きしないでください。同じUDN/データで二重起動しないでください。

旧アプリとv0.4.2の配布物を保持します。復旧時は旧アプリへ戻し、更新後に追加されたDB行や設定変更を確認してください。古いDBを無条件に上書きしません。
