# DLNA Video Server Public v0.4.1

v0.3.0からの更新候補です。製品SemVerは両版共通、Git SHAとビルド識別子は別です。

## 追加回帰監査後の変更

- AAC 2音声は観測可能な受信機互換プロファイルと配信先・入力条件で自動選択します。通常利用で個体UDN・素材fingerprintの登録を必須にしません。トラック数・形式・実行経路・時計監査は毎回検証します。
- 既存sourceScopeは素材例外として維持し、関連する例外を基本許可より優先します。CFR必須・stale・無効な例外を迂回しません。設定の自動拡張は行いません。
- WMA Pro入力許可は独立した限定許可のままです。ASFの未知平均レート0/0の判定と、ビルドに結合した再生回帰マトリクスを追加しました。
- 以前の候補合格判定は撤回し、今回の新しい許可構成の実機確認は別項目として扱います。

## 変更

- 受信機個体・sink能力・配信先・素材fingerprintを結合したWMA Pro入力許可を追加。未許可時の従来動作を維持。
- AAC 2音声許可とは独立に管理し、既定の個別許可は空のままです。
- ソース別の既存WMV／H.264 AVI補正機構を維持。VFR系では通常VFRを維持し、CFR系では適格な入力に既存CFRを自動選択します。別型番の実機成功を保証するものではありません。
- 管理APIに製品バージョンとビルド識別子を分離表示。同期候補の照合を追加。

## 検証範囲と制限

限定したREGZA個体・2素材で再生、2音声切替、Seek、Seek後切替を確認済みです。全WMA Pro・全REGZAへの保証ではありません。

- 一部WMA Proの全編終端は独立時計差約84.67／77.50msにより64ms監査に失敗します。通常再生・Seek成功とは別の既知制限です。
- WMA v2の一例はHTTP自然EOFに成功しましたが、末尾無音AAC約64msの省略と時計契約が未解決です。
- Python依存の共通PCM時計・サンプル索引は正式機能ではなく、通常JITへ接続しません。
- 未解決の長尺映像ギャップ、音声約703ms超過、極末尾Seekの未採用変更は解決・採用していません。64ms監査は維持します。

## 更新

停止後の整合バックアップを保存し、新しいアプリフォルダーから既存dataを指定します。UDN、catalog、ObjectID、既存許可、PCR／Seek索引を初期化しません。同じdataで旧新版を同時起動しません。ロールバック前に更新後データとの差分を確認します。

## 公開判定

PublicはNodeのみ同梱し、FFmpeg/ffprobeは利用者が別途指定する従来方式です。Privateの同梱方式とは異なります。両版の検証結果を照合し、正式公開の承認を待ちます。
