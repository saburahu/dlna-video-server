# DLNA Video Server Public v0.4.1

v0.3.0から直接更新します。Node 24.22.0を同梱し、FFmpeg／ffprobeは同梱しません。利用者が用意した対応版のbinを標準Setupで指定してください。検証基準は8.1.2で、旧7.1.1は拒否します。追加のPython環境は不要です。

製品SemVerは両版共通0.4.1です。Git SHA・ビルドIDは版ごとに異なります。

## 主な変更

- 観測可能な受信機互換性プロファイルと入力動画の技術条件から、CFR／VFRとAAC 1／2音声を通常再生時に選択します。一般機能に個体UDN・作品fingerprintの事前登録を要求しません。情報不足・矛盾のある受信機へCFRを一律適用しません。
- CFR系では既存SD WMV3／H.264 AVIに加え、適格なSD WMV3 Main入りMKV、約23.976fps・1080p progressive H.264 High入りMP4を約29.97fps CFRへ変換します。VFR系の既存処理は維持します。
- 適格なASF／SD WMV3 Main＋WMA Pro stereoを技術条件付きで自動入力します。1音声44.1／48kHz、2音声48kHzなどの対応条件を検証し、未対応形式を無条件に開放しません。
- AAC 2音声を別PID・独立時計で多重化します。入力許可と音声能力は別に判定し、明示的な無効化・素材固有例外・CFR必須条件を維持します。
- 64ms音声終端監査、URL binding、入力時刻・TS監査、同時JIT制限、Seek、キャンセル・executor解放を維持します。研究用Python／PCM索引時計、診断A/B一覧・強制モードは通常配信へ導入しません。
- 管理APIの製品バージョンとビルドIDを分離し、両版の同期リリース照合と固定実行パスのWindows配布テストを整備しました。

## 検証と互換性の範囲

- 代表REGZA実機で通常再生、Seek、音声切替可能な素材の切替をユーザーが確認しました。CFR一般化前のA/B結果に加え、通常Privateビルド586d07cでの成功報告です。素材別・受信機別に未報告の件数や、全機種の成功を推定しません。
- 共通再生コードについて型チェック、ビルド、自動テスト、隔離HTTPの映像・音声・TS・Seek・拒否・cleanupを検証しています。実機成功とPC検証、推定対応は区別します。
- 過去の約73分1音声VFRの全編HTTP成功は研究検証の証拠です。すべてのWMA Pro、2音声、CFR、REGZA実機の全編終了を保証するものではありません。

## 既知の制限

- 一部WMA Proは全編自然EOFで独立音声終端差が64ms監査を超え、HTTPが異常終了します。再生開始・Seekの成功と自然EOFは別です。短い予告でも発生します。
- WMA v2の一例では自然EOFが成功しますが、末尾無音AAC約64msの省略と時刻契約に未解決事項があります。
- MKV入力の417ms間隔・復号警告は解消していません。Vorbis副音声は未対応で、AC3主音声のみになる組合せがあります。
- 未解決の長尺映像不連続、約703msのPCM終端超過、未採用の極末尾Seek変更は解決していません。監査閾値を緩和せず拒否・安全制約を維持します。
- 未確認の型番、VC-1／HD WMA Pro／5.1・96kHzなどへの無条件対応を保証しません。

## 更新・ロールバック

旧サーバーを正常停止して整合バックアップを取り、新しいアプリから既存のデータ領域を指定してください。設定・許可・UDN・Friendly Name・catalog・ObjectID・PCR／Seek索引は継続使用し、同じデータで二重起動しないでください。旧アプリを保持し、ロールバック時は更新後のデータ差分を確認します。古いDBを無条件に上書きしないでください。
