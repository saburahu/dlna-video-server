# DLNA Video Server public v0.4.2 開発候補

公開済み0.4.1を基準とした0.4.2開発候補です。実機未確認であり正式公開しません。

直接の子が1000件以下なら現状を維持します。超える場合は実サブフォルダーを先に残し、動画を1–1000、1001–2000など固定範囲へ投影します。最後の範囲名も1000件単位です。実フォルダー999＋動画2000では、999実フォルダーと「動画」中間ノードを置き、その下に範囲2件を置きます。実フォルダーが1000件以上かつ動画がある場合はフォルダー範囲と「動画」を用い、実フォルダーだけでも1000件超なら範囲へ階層化します。百万件を超える場合は上位範囲を必要に応じて作り、各ノード1000件以下を保証します。

「すべて」はTSの既存順を先頭、通常動画の既存DB順を後続として一つの通し番号で分割します。「すべて」は元の場所・ObjectIDを維持し、範囲をサーバールートに並べません。

virtual/v1/名前空間に基点ObjectID・種類・開始番号・範囲幅を可逆符号化し、仮想IDを再起動後も安定化します。元ファイル・実ディレクトリ・DBスキーマ・既存動画/フォルダーIDは変えません。表示parentIDのみ投影先に合わせます。別ルートでの同じ素材は従来の別配置IDを保持します。実フォルダーと範囲の同名はIDで区別します。

BrowseDirectChildren、BrowseMetadata、TotalMatches、childCountは投影後の直接の子数です。1回の応答は従来の200件上限です。DIDL生成・stat・JIT装飾は要求ページだけで行い、グループ化のための全件DIDL生成・probe・索引再構築は行いません。フォルダーの元件数/位置は既存SQL索引から取得します。

追加・削除・並び順変更に伴う既存UpdateIDに、投影版番号1を加え、新版導入時の一覧更新を区別します。古い範囲が消えた場合は空応答となります。大規模変更前の一覧を端末が保持した場合は一覧の再取得が必要です。

再生URL、元コンテンツ、CFR/VFR・WMA入力・AAC/Seek・64ms・URL binding・同時制限を変更しません。serverの変更は統合BrowseがTSの元ページを指定できる引数の受け渡しのみです。

既知のWMA自然EOF、MKV入力警告、Vorbis副音声未対応は0.4.1と同じです。64ms監査を維持。PublicはFFmpeg/ffprobe非同梱です。
