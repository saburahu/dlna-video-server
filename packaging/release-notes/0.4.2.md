# DLNA Video Server Public v0.4.2

v0.4.1からの更新です。両版の製品バージョンは共通0.4.2、ビルドID／Git SHAは別です。

Node.js24.22.0同梱、FFmpeg／ffprobe非同梱の標準Windows x64版です。対応する外部FFmpegを従来どおりSetupで指定してください。検証基準は8.1.2です。

## 大規模DLNAライブラリのBrowse改善

- 直接の子項目が1000件以下なら既存の階層を維持します。1000件を超える一覧を、1–1000、1001–2000などの仮想範囲フォルダーへ分割します。最終範囲名も固定幅です。
- 実サブフォルダーを優先して残し、直下の動画をまとめます。実フォルダーと範囲の合計が上限を超える場合は、中間階層を必要な分だけ追加します。実フォルダーだけで1000件を超える場合や、多段階が必要な場合も各階層の直接の子を1000件以下にします。
- ルートの「すべて」は維持し、その内側でTSと通常動画の既存順を通して分割します。サーバールートへ範囲を並べません。
- 実ファイル・ディレクトリ・DBスキーマ・既存ObjectID・再生URLを変更せず、Browse上のparentIDと件数を投影先に合わせます。仮想IDは再起動後も安定します。
- BrowseMetadata／BrowseDirectChildren、childCount／TotalMatches／UpdateIDを整合させ、SOAPの1応答200件上限を維持します。要求ページだけを描画し、全件DIDL生成や索引再構築は行いません。

## 検証範囲

- Private642件／Public580件の自動テスト、型チェック・ビルド、境界999／1000／1001／2000／2001、混在・多段階、追加削除・並び替え・metadata・ページングを検証しました。
- 保存済みの実DBコピーでは「すべて」6955件を隔離HTTPで全列挙し、順序・ID・parentIDを照合して重複／欠落0を確認しています。件数は検証時点のもので、実ファイルの全編再生を意味しません。
- Private 8d5d817について、ユーザーからREGZA ZP2で「動作確認しました。バッチリです」と成功報告を受けました。個々の境界や全ファイルをすべて実機確認したとは推定せず、他のDLNA機器の動作も保証しません。本機能自体は機種・個体・作品に依存しない一般的なBrowse機能です。
- CFR／VFR、WMA入力、AAC 2音声、Seek／TimeSeek、64ms監査、同時制御、URL binding、キャンセル・cleanupの実行コードは実機成功候補から変更していません。

## 更新と既知の制限

旧サーバーを正常停止し、整合バックアップを取得してから標準アプリを交換し、従来のデータ領域を継続使用してください。設定・UDN・catalog・ObjectID・受信機許可・PCR／Seek索引を初期化せず、旧アプリは保持してください。同じUDN／データ領域の二重起動を避け、ロールバック時は更新後データとの差分を確認します。

端末が古い一覧を保持する場合はサーバー／フォルダー一覧を再取得してください。新規録画・削除で境界の番組名は移動しますが、元ObjectIDは維持します。旧範囲が消えた場合は空応答になります。

WMA Pro自然EOF、WMA v2末尾無音の時刻契約、MKV入力警告、Vorbis副音声未対応などv0.4.1の既知制限は継続します。64ms監査を緩めず、研究用PCM時計や未採用Seek修正は導入していません。
