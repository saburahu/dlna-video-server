# 不具合報告とログ

[困ったとき](TROUBLESHOOTING.md) ／ [不具合Issue](https://github.com/saburahu/pt3-recording-server/issues/new?template=bug_report.md)

## まず記録する内容

サーバー版、Windows版、[FFmpeg／ffprobeの版](FFMPEG.md)、再生機器のメーカー・型番、入力コンテナと分かる範囲の映像／音声codecを記録します。codec不明なら不明で構いません。症状、再生開始／Seek／停止の操作、再生位置、おおよその日時（タイムゾーン付き）も必要です。

「一覧に出ない」「選択時エラー」「黒画面・無音」「再生途中の破綻」は分けてください。端末のフリーズや再起動があった場合、再試行せずその旨を記録します。

## 保存先を確認する

1. サーバーPCで管理画面（既定 `http://localhost:19090`）を開きます。
2. 「診断」の「ログ・試行を更新」で、ログ保存先と保存エラーを確認します。
3. エクスプローラーでその保存先を開きます。ポータブル版では通常、Setupで選んだdataフォルダ内のlogsです。既定dataは `%LOCALAPPDATA%\PT3 Recording Server`（エクスプローラーのアドレス欄では環境変数を展開できます）。
4. 問題の時刻を含む `diagnostics.jsonl` と必要なローテーション世代から、関連範囲だけを**別ファイルへコピー**します。起動できない場合は同じlogs内の起動stdout／stderrを確認します。元ログは編集しません。

JSONLは1行1記録です。ログ時刻はUTC（末尾Z）、日本時間は+9時間です。Browse・HTTP要求・応答・送信進捗・終了理由を対応付けるため、失敗行だけでなく、その前後も含めてください。ローテーションで過去ログが消える前に、必要な範囲をローカルへ退避します。

Diagnose.cmdの出力も配置・runtimeの診断に使えますが、公開前にパス等を確認します。Status.cmdやportable-running.jsonにはロックtoken等があるため、その全文を公開しないでください。

## 公開前の確認

GitHub Issueは誰でも閲覧できます。コピー側の内容を読み、以下を伏せてください。

- 録画タイトル、個人名、ユーザー名、録画フォルダやホームの実パス
- IPアドレス、ホスト名、UDN、シリアル番号、機器識別子
- token、password、秘密鍵、Authorization、Cookie等の認証情報
- 内部URLや公開すべきでないネットワーク情報

同じ値は同じ仮名（例「端末A」「動画A」）に置き換え、時刻・要求順・ステータス・バイト数・codecは可能なら残します。自動マスク済みとは仮定しないでください。

**録画・動画本文、通信キャプチャ、SQLite catalog、設定全体、PCRキャッシュ、dataフォルダ全体は添付しません。** まず短いマスク済みログと症状を報告し、追加情報が必要なら対象を絞ります。秘密情報を誤って投稿した場合は、投稿を消すだけでなく漏れた認証情報の失効も検討してください。
