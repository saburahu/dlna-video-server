# v0.2.0の導入検証範囲

v0.2.0の導入検証範囲です。当時の変更はWebドキュメントとIssueテンプレートのみで、v0.2.0のZIP・Release・実行コードは変更していません。その後のv0.2.1修正は[変更履歴](../CHANGELOG.md)を参照してください。

独立した公開ソースで型チェック・全452テスト（失敗0・skip 0）・ビルド成功。文書内の相対リンク37件を検査し、公開許可リスト・機密情報パターン検査の指摘は0件でした。パターン検査だけで未知の秘密情報が存在しないことを完全に証明できるものではありません。

## 実施したこと

公開ReleaseのWindows ZIPと、別配布のGyan FFmpeg／ffprobe 8.1.2を取得し、SHA-256を照合しました。ZIPのSHA-256は `4473610c69c146fe08dede71b3695b11284ede595a41ec9ee8fb4ea01d6f6bbd` です。

Windows 11の隔離された一時配置先に、アプリ・data・合成動画・外部FFmpegを分けました。PATHからNode.js、FFmpeg、ffprobe、Gitを外し、開発プロジェクトのnode_modulesや設定に依存しない状態で、公開ZIP同梱のNode.jsから起動しました。

## 確認できていないこと

- クリーンWindows VMは利用できず、Windows 11ホスト上の隔離試験です。既存OSのコンポーネントが一切ない環境やWindows 10の新規導入は未確認です。
- 実CMD／PowerShellへ標準入力で回答し、ブラウザ自動起動を抑止しました。実際のキーボード操作・SmartScreen・ブラウザ起動ダイアログは未確認です。
- 稼働DMSと干渉しないよう、検証だけSSDP広告を無効化しloopbackへ限定しました。この試験では物理テレビからの発見・再生、Firewallの対話、NAS権限、自動ログオン起動の登録を検証していません。
- 更新はアプリ保存先の切り替えです。存在しない次バージョンへのDB移行を実証したものではありません。
- 今回の新規配置テストはDirect Play中心です。JIT・2本同時実行・TimeSeekのPC回帰と実機の範囲は[動作実績](COMPATIBILITY.md)を参照してください。

## 見つかった導入上の問題

Setupは通常、最後にサーバーを起動します。旧案内のように直後にStart.cmdを開くと二重起動となるため、Web手順を訂正しました。既存Releaseの文書は保存したままです。

FFmpeg入力はexeそのものではなく両exeのあるbinフォルダです。引用符・環境変数をSetupの入力欄へそのまま入れない説明を追加しました。

v0.2.0のCMDラッパーは、FFmpeg不足等で失敗しても最後のpauseにより終了コード0になる場合があります。エラー表示・設定作成・起動結果で判定します。今回、終了コード処理の修正版を既存ZIPへ上書きしていません。自動導入ツールからの利用ではこの制約に注意してください。
