# AAC 2音声の受信機能力と素材例外

2音声切替は、実証した受信機個体と配信先プロファイルの能力として登録します。
`dualAudioPermissions`の`sourceScope`がないレコードが基本許可です。deviceId、
sinkHash、implementationFingerprint、targetProfile、有効なreferenceを照合します。
モデル名や拡張子だけで許可せず、配布既定値へ個体を登録しません。

基本許可があれば、後から追加した対応動画を作品別に登録する必要はありません。
毎回、実コンテナ・映像形式・トラック数・音声形式・サンプルレート・チャンネル・
ソース時計・実行デコーダーとJIT経路を検証します。2音声は同時に独立AAC PIDへmuxし、
受信機側で切り替えます。未対応構成は従来の1音声fallbackまたは入力拒否です。
形式適格性は既存の限定範囲（WMV3/WMA Proまたはv2の48kHz stereo×2、
SD H.264 High AVI/MP3×2、既存のH.264 MP4/AAC-LC×2・HEVC MKV/AAC-LC×2）を維持します。

## 素材例外との優先順位

既存の`sourceScope`付きレコードは、素材固有・実験的な例外としてそのまま読めます。
基本許可と素材例外は同じ個体・配信先に共存できます。

1. 関係する個体・配信先だけを選ぶ。基本許可が複数なら曖昧として拒否。
2. 例外の構造を検証。壊れた例外や不足fingerprintは基本許可で迂回しない。
3. 同じソースpathの例外があれば優先する。size/mtime不一致、無効化、能力不一致、
   CFR必須条件不成立、例外重複なら2音声不採用。基本許可への暗黙fallbackは禁止。
4. そのソースに関係する例外がなければ、個体・配信先の基本許可を使う。
   別作品だけの有効な例外によって、新しい対応素材を拒否しない。
5. 選ばれた許可にかかわらず、動画・音声の実構成と時計を検証する。

素材限定許可しかない既存設定を、黙って基本許可へ拡張しません。
以前からの基本許可を、追加素材だけのscopeへ狭めることもしません。
明示したCFR必須例外は、基本許可を追加しても有効です。

## 入力許可は独立

`wmaInputPermissions`は別の入力許可です。2音声能力の登録は、WMA Pro入力を
全素材へ許可せず、共通PCM時計を有効にせず、自然EOF問題を解決しません。
グローバルsource-clock-v1、個別source-clock-v2、64ms監査を維持します。
WMA Proは対象固有の入力条件を別途確認し、必要な限定許可だけを提案します。
通常VFR・Seek・A/V時計・既存のCFR個別許可も変更しません。

## コピー上での明示的な能力許可案

Windows配布物には以下のCLIを含みます。個体の音声切替成功を人が確認したうえで、
現在の能力情報とpolicyのコピーから新しい提案ファイルを作成します。

```
runtime\node.exe app\src\prepare-dual-audio-receiver-proposal.js policy-copy.json capability.json legacy-jp-observed "individual switching evidence" NEW-proposal.json
```

既存の素材例外・WMA入力・CFR設定を保持し、基本許可だけを追加します。
追加するsource fingerprintは0件です。入力ファイル・既存出力を上書きせず、
実サーバーに接続せず、稼働設定へ自動適用しません。停止・切替は別途承認が必要です。
無効・古い個体能力や曖昧な基本許可の再有効化は自動で行いません。

基本許可と素材例外の共存は、この判定を実装した新ビルドが必要です。
同じ製品番号0.4.1でも以前のビルドは同一個体・配信先の複数レコードを拒否します。
新提案を旧ビルドへ先に適用しないでください。将来の切替時はアプリとpolicyの
直前バックアップを保持し、ロールバックは更新後policyのハッシュ・差分を確認して
旧アプリと旧policyを一組で復旧します。DBやUDNを無条件に古いコピーで上書きしません。

## リリース回帰マトリクス

`test/playback-compatibility-matrix.test.ts`は匿名受信機・実際のcodec構成を使い、
既存と新規素材、基本許可と例外、入力許可、URL採否、JIT先、独立PID、VFR filter、
未許可個体・形式、古いfingerprint、CFR必須条件の優先順位を固定します。
ASFの未知平均レート`0/0`は既存の公称23.976fps証拠で評価しますが、既知の別レートや
不正な値を上書きせず、VFRの時刻を書き換えません。

`packaging/playback-compatibility-gate.mjs`は両版の実コミットに結びついた必須ケースの
証拠を確認します。`release-sync.mjs --compatibility-evidence FILE`で照合し、公開判定時は
必須です。ケース欠落・失敗・古いSHA・64ms変更・VFR非維持は不合格です。
自動テスト、隔離実HTTP、過去の実機記録、新ビルドの実機確認を別々に記録します。
HTTP 200やテスト総数だけでは実機互換性の成功としません。
