# 対応形式と受信機の制限

[README](../README.md) ／ [症状別の確認](TROUBLESHOOTING.md)

DLNA Video ServerはREGZAテレビ・レコーダー向けの互換性を重視して開発しています。
メーカー公式の製品・ソフトウェアではなく、REGZA全機種の対応を保証しません。
REGZA以外のメーカー製品で動作確認済みという意味でもありません。

## 再生方式

| 利用先 | 基本方式 | 注意 |
|---|---|---|
| 能力と要求実装を確認できるREGZA受信機 | AVC + AACのJIT、192-byte TTS | ブランド名だけでは許可しません。 |
| 独立PCRのMPEG-2方式を必要とする、対応するREGZAレコーダー | MPEG-2 video + AAC、独立PCR PIDのJIT、192-byte TTS | 同一ブランドでも要求実装は異なります。すべてのレコーダーに適用しません。 |
| VLC | 元ファイルのHTTP Direct Playを優先 | 復号・音声切替はクライアント側の能力に依存します。JIT枠を消費しません。 |
| 通常の非保護放送TS | 通常TS配信とPCR索引によるTimeSeek | 索引の準備状態と端末の一覧キャッシュに注意してください。 |

## 入力形式

TS、MP4、MKV、AVI、WMV／ASFの一部構成を扱います。拡張子と実際のcodec・profile・
ストリーム構成は別です。代表的な入力はH.264／HEVC／MPEG-2／MPEG-4／WMV映像と
AAC／MP3／WMA音声ですが、名前だけで全組み合わせの対応を判断しません。
破損、暗号化、未対応codec、音声なし、特殊な複数streamや字幕等には制限があります。
DRM解除機能はありません。

[限定2音声JIT](MULTI-AUDIO.md)は入力条件と受信機個体の明示的許可が必要です。
既定は1音声です。Direct Playでは元のトラックを保持しますが、選択・復号は受信機側の機能です。
JITは最大2本のCPUソフトウェア変換で、GPUは必須ではありません。
高解像度や重い入力でも常に2本の速度が出る保証はありません。

## 検証範囲

一部のREGZAテレビ・レコーダーで通常TS、対応するAVC／MPEG-2 JIT、TimeSeek、
限定構成の音声切替の実績があります。動作は受信機実装と入力ファイルに依存します。
自然終了の確認範囲も入力・再GETの有無で異なり、すべての受信機で先頭から全編連続配信を
確認したという意味ではありません。

Node.js 24.22.0と外部FFmpeg／ffprobe 8.1.2でPC検証と限定したREGZA受信機の再生確認を
行っています。全機種・全機能・全形式を再検証したものではありません。
PC自動検証では合成素材の配信・復号・Seek・終了・2本同時JITを確認します。
PCで復号できてもテレビでの正常表示や安全な再試行を保証しません。
[導入検証の範囲](ONBOARDING_VALIDATION.md)も参照してください。

## 共通の制限

- 管理画面・管理APIはサーバーPCのlocalhostからのみ利用できます。
- 現在の受信能力、要求実装、発行resourceを照合し、不確かな条件ではJITを公開しません。
- 通常TSの索引未生成時の一覧を端末が保持すると、タイムバーやSeekが無効のままの場合があります。
- 一部の古い音声形式では自然終了時の時計検証に失敗します。
- 一部のREGZAレコーダーと動画ファイルの組み合わせで、再生系が正常に復帰できなくなる
  事象を確認しています。未解決であり、同じファイルの再試行を繰り返さないでください。
- 終端付近への極短いSeekには制限があります。新しい終端索引・事前判定は未採用です。

詳しくは[既知の問題](KNOWN-ISSUES.md)を確認してください。
